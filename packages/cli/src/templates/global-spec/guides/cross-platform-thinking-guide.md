# 跨平台思考指南

> 机器级通用思考指南，用于避免把某个平台、Shell 或本机路径假设写死到项目规则里。

---

## 适用场景

- 编写脚本、命令示例、hook 或 agent 配置。
- 规则需要同时服务 Codex、Cursor、Pi、Claude Code 等多个入口。
- 文档里出现绝对路径、平台专属命令、环境变量或本机工具。

---

## 检查问题

- 这个路径是项目相对路径、skill 相对路径，还是本机绝对路径？
- 这个命令是否依赖 macOS、zsh、GNU 工具或特定 Node/Python 版本？
- 这个规则应该写入机器级基线、项目级 spec，还是任务 PRD / info？
- 其他平台是否通过同一个 JSONL/spec 注入契约拿到这条规则？

---

## 基线规则

- 机器级规则可以引用本机真源路径，但项目接入方式必须显式，例如符号链接或 JSONL 条目。
- 项目级文档优先使用仓库根目录相对路径，除非任务目标就是配置本机全局路径。
- skill 内的 `scripts/...`、`references/...` 等资源按 skill 根目录解析，不按目标项目根目录解析。
- 涉及多平台 agent/hook 时，先说明共享契约，再说明平台差异。

---

## 完成前核对

- [ ] 没有把某台机器的临时路径写成项目通用事实。
- [ ] 没有把某个平台的 hook 行为当成所有平台都会自动执行。
- [ ] 需要显式选择启用的规则，文档中写清了选择启用入口。
- [ ] 如果使用符号链接，已验证链接目标存在且后续上下文扫描能看到它。
