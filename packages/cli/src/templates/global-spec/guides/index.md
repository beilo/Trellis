# 思考指南

> **目的**：扩展思考范围，捕捉你可能尚未考虑到的问题。

---

## 为什么需要思考指南？

**大多数缺陷和技术债都来自“没想到这一点”**，而不是能力不足：

- 没想到层边界处会发生什么 → 跨层缺陷
- 没想到代码模式会重复 → 到处都是重复代码
- 没想到边界情况 → 运行时错误
- 没想到未来维护者 → 代码难以阅读

这些指南帮助你在编码前**提出正确的问题**。

## 快速参考：思考触发点

### 何时思考跨层问题

- [ ] 功能触及 3+ 层（API、Service、Component、Database）
- [ ] 数据格式在层之间发生变化
- [ ] 多个消费者需要相同数据
- [ ] 你不确定某段逻辑应该放在哪里

→ 阅读 [跨层思考指南](./cross-layer-thinking-guide.md)

### 何时思考代码复用

- [ ] 你正在编写与已有代码相似的代码
- [ ] 你看到同一模式重复出现 3+ 次
- [ ] 你正在向多个位置添加新字段
- [ ] **你正在修改任何常量或配置**
- [ ] **你正在创建新的工具/辅助函数** ← 先搜索！

→ 阅读 [代码复用思考指南](./code-reuse-thinking-guide.md)

### 何时思考跨平台问题

- [ ] 编写用户会直接运行的脚本
- [ ] 添加用法示例或帮助文本
- [ ] 处理文件路径或命令
- [ ] **从 shell 脚本迁移到 Python**

→ 阅读 [跨平台思考指南](./cross-platform-thinking-guide.md)

## 修改前规则（关键）

> **修改任何值之前，始终先搜索！**

```bash
# 搜索你将要修改的值
grep -r "value_to_change" .
```

这个简单习惯可以避免大多数“忘记更新 X”的缺陷。

3. **出现缺陷后**：把新洞察添加到相关指南（从错误中学习）
