# 规则归属基线

> 规定机器级规则、项目级规则和任务级文件分别应该写什么。

---

## 机器级规则

适合写入 `/Users/am/.trellis/spec/**` 的内容：

- 跨多个项目都成立的 AI 工作流要求
- 前端/后端通用工程纪律
- 修改前搜索、最小改动、验证记录、风险说明等质量底线
- 规则优先级、上下文加载和子代理输入边界

## 项目级规则

应保留在项目 `.trellis/spec/**` 的内容：

- 目录结构、模块边界、命名风格和组件组织
- 真实 API 契约、字段含义、接口封装和错误码
- 框架版本、构建命令、lint/type-check/test 命令
- 业务页面、业务流程、兼容规则和历史坑位

## 任务级文件

应写在 `prd.md`、`info.md` 或 `research/**` 的内容：

- 本次任务的目标、验收标准、非目标和用户拍板结果
- 临时兼容策略、迁移窗口和回滚计划
- 当前任务调研得到的具体源码证据
- 本次允许偏离机器级或项目级规则的原因

## 冲突处理

- 项目规则与机器级规则冲突时，先判断项目规则是否描述了真实代码事实；真实项目事实优先。
- 任务需求与项目规则冲突时，必须在 PRD / info 中记录冲突点和用户确认。
- 机器级规则升级时，只修改确实跨项目通用的部分；项目特例不要反向写入机器级基线。
