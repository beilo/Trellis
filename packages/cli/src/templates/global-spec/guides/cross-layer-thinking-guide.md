# 跨层思考指南

> **目的**：实现前梳理跨层数据流。

---

## 问题

**大多数缺陷发生在层边界处**，而不是层内部。

常见跨层缺陷：
- API 返回格式 A，前端期望格式 B
- 数据库存储 X，服务转换为 Y，但丢失了数据
- 多层以不同方式实现同一逻辑

---

## 实现跨层功能前

### 第 1 步：映射数据流

画出数据如何流动：

```
Source → Transform → Store → Retrieve → Transform → Display
```

对每个箭头提问：
- 数据是什么格式？
- 可能出什么问题？
- 谁负责验证？

### 第 2 步：识别边界

| 边界 | 常见问题 |
|----------|---------------|
| API ↔ Service | 类型不匹配、字段缺失 |
| Service ↔ Database | 格式转换、null 处理 |
| Backend ↔ Frontend | 序列化、日期格式 |
| Component ↔ Component | props 形状变化 |

### 第 3 步：定义契约

对每个边界：
- 精确的输入格式是什么？
- 精确的输出格式是什么？
- 可能出现哪些错误？

---

## 常见跨层错误

### 错误 1：隐式格式假设

**坏例子**：不检查就假设日期格式

**好例子**：在边界处显式转换格式

### 错误 2：分散验证

**坏例子**：在多层验证同一件事

**好例子**：在入口点验证一次

### 错误 3：泄漏抽象

**坏例子**：组件知道数据库结构

**好例子**：每一层只知道相邻层

---

## 跨层功能清单

实现前：
- [ ] 已映射完整数据流
- [ ] 已识别所有层边界
- [ ] 已定义每个边界处的格式
- [ ] 已决定验证发生在哪里

实现后：
- [ ] 已用边界情况（null、空、无效）测试
- [ ] 已验证每个边界处的错误处理
- [ ] 已检查数据能完成往返

---

## 何时创建流程文档

在以下情况创建详细流程文档：
- 功能跨越 3+ 层
- 涉及多个团队
- 数据格式复杂
- 功能此前导致过缺陷
